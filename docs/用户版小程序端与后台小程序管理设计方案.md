## 二、先说清楚「上传即用」到哪一步（边界诚实说明）

微信小程序的发布**绕不开微信侧**：代码必须经微信开发者工具（或 `miniprogram-ci`）上传 → 微信后台提交审核 → 发布，用户才能在微信里搜到 / 扫码进入。所以「管理员在平台后台上传代码包 → 用户就能用」在技术上**不能字面成立**。本方案把这件事拆成三件确实能做到的事：

1. **代码包版本托管**：管理员把小程序代码包（zip）上传到平台后台，登记版本 / 渠道 / SHA-256 / 变更说明 / 最低基础库，形成可下载、可回溯的版本台账（同 `HwDevKit` 口径）。
2. **小程序码托管与分发**：后台配置小程序 AppID / AppSecret 后，调用微信 `wxacode.getUnlimited` 生成小程序码；未配凭据时允许管理员手工上传小程序码图片。小程序码用于服务号菜单、官网、物料分发。
3. **配置下发**：站点域名、小程序名称、主题色、功能开关由后台维护，小程序启动时读取，做到「改配置不发版」。

**平台内置默认包 + 管理员可覆盖**：仓库随代码版本携带一份默认小程序包（`miniprogram/`，随构建产出），后台「小程序管理」页默认展示内置包版本；OEM 客户可上传自己的定制包覆盖。

> **阶段二（已实现）**：接入微信官方 `miniprogram-ci`——管理员在后台填**代码上传密钥**后，后台把代码直接上传到微信（生成开发版），可省去本地开发者工具一步；**但提交审核与发布仍需在微信公众平台完成**（微信不开放自动发布接口给普通主体）。详见 §六.1，界面文案已明确「上传≠上线」。

## 三、哪些功能适合放进小程序（取舍表）

口径：**「一屏一动作」的事务型待办进小程序；「配置 / 编排 / 可视化 / 大表单」留在 Web**。约束是小程序主包 ≤ 2MB、总包 ≤ 20MB，且不宜承载复杂交互与文件处理。

### 3.1 建议进入小程序（移动办公延伸）

| 功能 | 对应现有能力 | 小程序内形态 | 理由 |
| --- | --- | --- | --- |
| **我的任务**（统一任务中心） | `/tasks`、任务中心八类待办 | 列表（按来源 / 分组筛选）+ 详情 + 去处理跳转 | 高频、事务型，手机处理最合适 |
| **OA 审批** | `/oa`、`/m/oa/[id]` | 待我审批列表 + 详情 + 通过 / 驳回 / 转交 | 审批就是「一屏一动作」 |
| **AI 客服会话 / 售后工单** | `/service-desk`、`/m/service/[id]` | 会话列表 + 会话详情 + 回复 / 转工单 | 客服需随时响应，移动端刚需 |
| **系统消息 / 通知中心** | `/notifications`、`/m/inbox` | 六类事件分类列表 + 详情处理 | 与服务号推送天然互补 |
| **待办概览首页** | 驾驶舱「我的待办」 | 首页卡片：待办数、未读、今日到期 | 小程序首页，一眼看全局 |
| **身份 / 主体切换（轻量）** | 顶部主体切换器 | 切换当前组织 / 身份，只读展示 | 多身份用户移动端必备 |
| **只读查询（次要）** | 我的签约 / 我的套餐进度 | 只读列表 + 详情 | 只需展示，成本低 |

### 3.2 建议**不**放进小程序（留在 Web）

| 功能 | 不进的理由 |
| --- | --- |
| BI 智能分析 / 报表 / 仪表板 | 图表与筛选交互依赖大屏，小程序体验差 |
| 工作流画布、AI 画布、低代码编辑器 | 拖拽画布与复杂编排，主包体积与交互都不适配 |
| 多维表格、进销存 / ERP、财税申报 | 大表格录入与批处理，非移动场景 |
| 数字资产 / 内容创作（生图 / 视频 / 音乐） | 上传下载大文件、长时任务，不适合小程序 |
| 商务社交 / 招聘信息流、供需市场浏览 | 属对外获客方向（本次已确认不做） |
| 平台管理后台 `/admin` | 管理端只在桌面 |

> 说明：以上「不进」项不是能力缺失，而是**移动端不做**——Web 端原有入口与地址完全不变。

## 四、小程序端设计

### 4.1 工程与技术选型

- **第一方工程 `miniprogram/`**（仓库根目录，与 `hardware-devkit/` 同级），采用**微信原生小程序**（WXML / WXSS / JS + `app.json` 分包）：主包只放公共框架与首页，各业务页按分包拆，控制主包体积。
  - 不选 Taro / uni-app：本场景页面少、逻辑轻，原生省掉一层构建链，离线可编译、体积最小；**也不做纯 web-view 壳**（已确认排除）。
- **打包脚本 `scripts/pack-miniprogram.mjs`**（对齐 `pack-extension.mjs`）：把 `miniprogram/` 打成
  `update/miniprogram/miniprogram-<版本>.zip`（后端内置包目录即 `<update>/miniprogram`），产出 SHA-256 与体积，供后台上传或随平台发布内置。
  版本优先级与后端 `currentVersion()` 一致：`MINIPROGRAM_VERSION` → `release-manifest.json` → git tag；
  接口域名可用 `MINIPROGRAM_API_BASE` 注入到包内 `config.js`（微信要求 request 合法域名预先登记，域名本质上随包带出）。
- **启动引导**：小程序 `app.js` 启动时拉 `GET /api/public/miniprogram/bootstrap`，取站点域名、小程序名、主题色与功能开关（决定哪些 tab 渲染），避免把域名写死在代码里（对齐「客户域名归客户」口径）。
  接口基址本身由包内 `config.js` 提供，并可在端上「我的 → 服务器地址」覆盖并保存。

### 4.2 登录与会话

1. 小程序调 `wx.login()` 拿 `code`。
2. `POST /api/public/miniprogram/login`（`{ code }`）：后端用配置的 **小程序 AppID / AppSecret** 调微信 `code2Session`，拿 `openid` / `unionid`。
3. **绑定匹配**：优先按 `unionid` 命中既有 `WechatMpBinding`（同一主体下服务号已绑定的账号直接免登）；命中则签发本站 SSO 会话令牌。
4. **未命中**：返回 `unbound`，小程序引导「账号密码 / 验证码登录后绑定」，绑定成功写 `WechatMpBinding`（`source = miniapp`）。
5. **会话承载**：令牌由小程序存入 `storage`，后续请求走 `Authorization: Bearer <token>` 头——现有 `sessionToken(c)` **已支持头优先**，无需为小程序另建一套会话。

> 复用服务号同一套 AppSecret 加密存储（`WechatMpCrypto` / `EXTERNAL_CRED_KEY`），小程序凭据只多一个 AppID / AppSecret，加密口径一致、后台只回掩码。

### 4.3 页面清单（对应现有 H5 与接口）

| 小程序页面 | 对应 H5 | 复用接口（站内契约） |
| --- | --- | --- |
| `pages/index`（工作台 / 待办概览） | 驾驶舱「我的待办」 | 任务中心 summary + OA 收件箱 + 客服会话 + 未读消息 |
| `pages/tasks`、`pages/task-detail` | `/tasks`、`/m/task/[id]` | 任务中心 list / detail / close / reopen / 表单提交 |
| `pages/oa`、`pages/oa-detail` | `/oa`、`/m/oa/[id]` | OA 审批 list / 申请详情 / approve / reject / transfer |
| `pages/service`、`pages/service-chat` | `/service-desk`、`/m/service/[id]` | 客服会话 list / detail / 回复 |
| `pages/notifications`、`pages/notification-detail` | `/m/inbox` | 通知 list / 标记已读 / 全部已读 / 关联链接 |
| `pages/me`（身份 / 绑定 / 退出） | — | `/enterprise/me`、身份切换、`miniprogram/status`、`miniprogram/binding` |
| `pages/login`（登录门 / 服务器地址） | — | 公开侧 `bootstrap` / `login`（微信一键或账号密码绑定） |

> tabBar 固定两项（工作台 / 我的）；任务、OA、客服、消息以工作台入口呈现，**功能开关关闭的入口整个不渲染**。

**复用口径**：业务接口**一律复用现有站内契约**，不新增业务后端；面板 / 列表 / 卡片样式**不复制 Web 组件**，按小程序原生控件重写（体积与体验）。

### 4.4 与服务号 H5（`/m/*`）的关系

- 小程序是「用户版」移动端的**主形态**（微信内的独立入口）。
- `/m/*` **保留**：服务号模板消息点开的落地页仍是 H5（微信内网页），两者共用同一批后端接口与同一份会话口径。后续可按需在 `/m/*` 顶部加「在小程序中打开」引导。

### 六.1 阶段二：后台直传微信（`miniprogram-ci`）

管理员在「小程序管理 → 基础配置」填 **代码上传密钥**（微信公众平台 → 开发管理 → 开发设置 → 小程序代码上传密钥）与 **机器人编号**（1–30，多人协作时用于区分上传者），密钥落库前加密（同 AppSecret 口径），回显掩码、留空即沿用。

- 入口：版本台账的**内置包**行与**已上传版本**行各有一个「上传到微信」动作，分别直传内置包或该版本包；上传成功登记「最近直传微信」（版本号 + 时间）。
- 上传前的两处必要处理：随包的 `project.config.json` 若为 `touristappid` 占位则替换为后台配置的 AppID；上传密钥**只经子进程标准输入传递**、不落工程目录（避免被打包上传）。
- **子进程隔离**：`miniprogram-ci` 是重依赖（类型图 300 个声明文件）且上传失败时会抛出未处理的 Promise 拒绝——直接在 API 进程里跑会把**整个后端进程带走**。因此上传在 `spawn(process.execPath, ['-e', ...])` 的子进程内执行，主进程只读取子进程写回的结果文件；子进程崩溃/超时（240s）都只表现为一条可执行的中文提示。
- 前置条件（缺失时给可执行提示，不抛笼统错误）：填 AppID、填代码上传密钥、把**本服务器公网 IP** 加入微信「小程序代码上传」白名单。
- 边界：**只做到「上传为开发版」**。提交审核、设置为体验版、发布上线仍在微信公众平台完成；后台不持有 OpenAI/微信开放平台的自动发布能力。

## 七、风险与限制

1. **微信侧发布不可绕过**（已在上文说明）：后台托管的是「包 + 二维码 + 配置」，提审 / 发布仍在微信公众平台；界面文案需避免让管理员误解为「上传即上线」。
2. **合法域名**：小程序 `request` 合法域名必须在**小程序后台**配置，且用**客户自有域名**；后台配置的 `siteDomain` 只做展示与二维码内容，改不了微信侧白名单。
3. **主包体积**：主包 ≤ 2MB，业务页须分包；上传代码包需做体积校验与提示。
4. **小程序无 Cookie**：会话改走 `Authorization` 头（现有能力已支持），不改动 Web 端会话。
5. **合规**：小程序类目需与服务范围匹配，纯内部办公工具与对外提供服务的资质要求不同——本方案定位内部办公，规避该风险。

## 八、验收标准

- 后台 `/admin/miniprogram` 可：配 AppID/AppSecret 并保存（回掩码）、上传新版本包并出现在台账、生成 / 上传小程序码、启停与删除版本、看到下载量。
- 后台可填「代码上传密钥 / 机器人编号」并保存（密钥回掩码），对内置包或已上传版本点「上传到微信」：凭据/白名单齐备时返回成功与版本号、登记「最近直传微信」；缺失时返回可执行的中文提示，且**后端进程不受影响**。
- 小程序可用：`wx.login` 后已绑定账号**免登**进入首页；未绑定账号可账号密码 / 验证码登录并完成绑定。
- 六个页面（待办概览 / 我的任务 / OA 审批 / 客服会话 / 系统消息 / 身份）数据与 Web 端**同源一致**，处理动作（审批通过驳回、回复、标记已读、关闭重开）落库生效。
- 功能开关关闭某 tab 后，小程序端整个 tab 不渲染。
- `pnpm typecheck`、`lint`、契约快照与迁移校验全绿。

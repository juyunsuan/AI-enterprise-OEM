# 建站管理 · 数字人小程序工具 设计方案

> 状态：已实现（后端 + 小程序模板 + 管理端）。
> 参考源码：《AI数字人分身系统》（PHP ThinkPHP6 多站点 SaaS + uniapp「小狐狸AI数字分身」，34 张 `fox_clone_*` 表）。
> **本方案不是移植参考源码，而是把它的业务能力按本项目技术架构（Next.js 16 + Hono + Prisma + antd 6 + zod 契约 + 原生微信小程序）重写一遍。**
> 参考源码只用于核对业务口径与字段语义，仓库内不复制其代码、文案、模板与图片。

---

## 一、产品口径（已与需求方确认）

| 决策点 | 结论 |
| --- | --- |
| 站点模型 | **每个本站用户都能建立自己的数字人小程序平台**，一人一站（`userId @unique`），站点编码 `siteCode` 创建后不变 |
| 小程序归属 | 每个站点是**独立微信小程序主体**：用户填自己的 AppID/上传密钥，后端把站点配置注入模板出包，用户可下载导入或一键直传自己的微信账号 |
| 模型服务 | **不接参考源码的供应商 Key**：形象训练 / 声音克隆 / TTS / 对口型全部走本系统「模型配置」新增的数字人渠道（`DigitalHumanChannel`），协议收口在 `dh.provider.ts`（fox / synclabs / custom） |
| 支付 | **照搬租户自有微信商户号（APIv3 直连 JSAPI）**：钱直接进站点主人自己的商户号，平台不经手；套餐分会员 / 算力 / 形象点 / 声音点四类 |
| 分销 | **两级分销完整保留**：订单实付分佣（一级 + 二级合计 ≤ 100%）、提现申请即冻结、退款按比例扣回；推广员开通支持 auto / manual / pay 三种 |
| 客服 | **复用现有 AI 客服**：站点绑定自己的 service-desk `siteKey`，小程序「在线客服」用 web-view 打开 `/embed/service-desk?key=…`，本业务不写客服代码 |
| 海报 | 后台只存版式坐标，头像与小程序码在**端上 canvas 合成**；服务器不装任何绘图软件 |

一句话产品定义：**每个本站用户都能开一个属于自己的 AI 数字人小程序——上传形象/声音、输入文案生成口播视频、卖会员与点数、做两级分销，代码包一键传进自己的微信账号。**

## 三、数据模型（25 张表）

### 3.1 租户与配置

- `digital_human_sites`：站点实例。品牌/开关/计价/新人礼/登录/克隆参数/分销参数均为 JSON 列（`brand` / `toggles` / `pricing` / `gift` / `login` / `clone` / `commission`），状态机 `DRAFT → ONLINE`，平台侧可置 `SUSPENDED` / `CLOSED`；`serviceDeskSiteKey` 指向 AI 客服站点。
- `digital_human_channels`：本站数字人供应商通道。协议 `fox | synclabs | custom`，能力 `voice-clone | body-train | tts | lipsync`；Key 用 `MiniAppCrypto` 同套 AES-256-GCM 加密，出参只回 `keyConfigured`。

### 3.2 会员与资产

- `digital_human_members`：站点会员（openid 归站点，与平台账号物理隔离）。三账户 `point / bodyQuota / voiceQuota`，另有会员到期、推广等级、佣金余额、邀请人两级链。
- `digital_human_balance_logs`：资产流水。**先写流水再落余额、同一事务**；`bizType` 覆盖 gift/recharge/tts/work/body/voice/admin/refund/card 等。

### 3.3 形象与声音

- `digital_human_bodies`：形象训练记录（源视频、封面、时长、状态 0/1/2）。
- `digital_human_voices`：克隆音色（样本音频、试听、speakerId、状态）。
- `digital_human_voice_groups` / `digital_human_preset_voices`：预设音色分组与音色（`siteId=0` 为平台公共库）。
- `digital_human_bgm_groups` / `digital_human_bgms`：背景音乐库。

### 3.4 合成与任务

- `digital_human_works`：作品。记录形象/音色/音频类型/文案/BGM/语速/字幕、阶段 `tts|lipsync|done`、结果视频与音频、扣费点数、失败原因与退款标记。
- `digital_human_tasks`：供应商任务。`callbackToken` 唯一定位回调，`kind` 区分 voice-clone/body-train/tts/lipsync，记录供应商任务 id、状态、attempts。

### 3.5 内容与运营

- `digital_human_swipers` / `digital_human_articles` / `digital_human_posters`：轮播、图文（help/notice/about/privacy/agreement）、海报版式。
- `digital_human_write_topics`：AI 写作模板/选题/克隆引导文案/朗读示例（`siteId=0` 平台公共库）。
- `digital_human_ai_records`：AI 写作调用记录（站点主人付费，按模块计量）。
- `digital_human_feedbacks`：意见反馈（文字 + 联系方式 + 图片）。

### 3.6 交易与分销

- `digital_human_packages`：四类套餐（vip/point/body/voice），含价格、赠送资产、限购、销量、推荐位。
- `digital_human_orders`：订单。`packageSnapshot` 固化套餐内容；状态 0 未支付 / 1 已支付 / 2 已退款 / 3 已关闭；`promoterId` 记录归因。
- `digital_human_card_batches` / `digital_human_cards`：卡密批次与卡密（未使用/已使用/已停用）。
- `digital_human_promoter_applies`：推广员申请（auto/manual/pay）。
- `digital_human_commissions`：佣金流水（两级、比例、余额快照）。
- `digital_human_withdraws`：提现申请（待处理/已打款/已驳回，申请即冻结）。

## 六、合成状态机（实现重点）

```
扣点数 → 建作品(status 0, stage tts) → 提交 TTS 任务
        → 回调/轮询完成 → 落音频 → 提交对口型任务(stage lipsync)
        → 回调/轮询完成 → 落视频(stage done, status 1)
任一步失败 → status 2 + failReason + 按 pointCost 原路退费(isRefund)
```

- **幂等**：`applyOutcome` 对已终态任务直接返回；订单 `markPaid` 用 `updateMany({status:0})` 原子占位。
- **回调定位**：`callbackToken` 唯一，杜绝跨站伪造完成任务；供应商只支持主动查询时由 `workStatus` 顺手推进一次。
- **失败退费**：`pointCost > 0 && !isRefund` 时 `applyBalance(+pointCost, bizType refund)`。
- **重试**：仅失败任务可重试，按原扣费重扣后复用原 `callbackToken` 重提。
- **纯音频**：不选形象时 TTS 完成即出音频作品，按 `priceTts` 计费；选形象按 `priceVideo`。

## 七、支付与退款

- 微信支付 APIv3 JSAPI：`prepay` 生成 `timeStamp/nonceStr/package/signType/paySign` → 小程序 `wx.requestPayment` → 回调 `AES-256-GCM` 解密验真 → `markPaid`。
- `markPaid` 原子置已支付后：发会员天数与三类点数（均写流水）、套餐销量 +1、触发两级分佣。
- 退款：`refundOrder` → 微信退款 → 订单置已退款 → 资产回收（扣到 0 为止，流水备注应回收量）→ `clawbackOrder` 扣回佣金。

---

## 八、两级分销

- 归因：下单时写 `promoterId = member.referrerId`；登录链接带 `tuid`，新会员落 `referrerId` 与 `parentReferrerId`。
- 入账：订单支付成功后按 `level1Rate / level2Rate` 对实付金额分佣，写 `digital_human_commissions` 并累加 `commissionBalance`。
- 提现：申请即从余额扣减（冻结），管理员审核打款或驳回（驳回退回余额）。
- 开通：auto 立即通过；manual 待审；pay 生成开通订单，支付成功自动通过。

## 九、小程序出包与发布

- 模板 `miniprogram-dh/`：`config.js` 保留 `apiBase / siteCode / siteName / themeColor` 四个空串槽，出包时按站点注入；`project.config.json` 注入 AppID。
- 流程：收集模板 → 注入配置 → 注入 AppID → 主包体积闸门（1.9MB）→ zip → 对象存储 → 出包台账 → 可选直传微信（仅开发版，提审在用户自己的公众平台）。
- 同站串行上传，避免微信侧版本互相覆盖；小程序码按站点生成并缓存复用。

## 十二、边界与风险

- 数字人业务表与 mall / knowledge-pay / card-shop / health 完全隔离，只共享私域底座（凭据、出包、令牌、OSS）。
- 供应商协议差异（回调字段、状态码、结果字段）统一在 `dh.provider.ts` 归一；新增供应商只加一个协议分支。
- 声音克隆在 synclabs 协议下仅支持 voice-clone，不支持 TTS/对口型，渠道能力探测会在管理端提示。
- 素材统一走对象存储公网 URL（限 100MB、扩展名白名单），供应商侧不接收本站私有地址。
- 平台停服（SUSPENDED）只冻结 C 端登录与合成，站点设置仍可保存，不会把停服站点拉回营业。

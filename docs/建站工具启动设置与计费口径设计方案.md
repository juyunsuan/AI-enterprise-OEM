# 建站工具「启动设置」与计费口径设计方案

> 适用板块：「建站管理」（`/site-builder`）下 9 个工具——知识付费 / 上门服务 / 品牌商城 / 健康管理 / 多店铺商城平台 / 数字人 / 卡密商城 / 快递寄件 小程序，以及国际独立站。
> 底座复用：积分总账 `PointsService`（原子条件扣减 + `idempotencyKey`）、价目表 `module_pricing`、日批范式 `GeoSiteBillingService` / `PointsBillingService`、功能开关前缀映射 `feature-catalog.data.ts`。

## 一、产品口径（已与需求方确认）

| 决策点 | 结论 |
| --- | --- |
| 启动粒度 | **工具级**：一个账号 × 一个工具 = 一条订阅。启动后该工具下所有站点/店铺可用，停止后全部不可用。 |
| 未启动的语义 | 不产生任何积分扣费；C 端公开接口停服、禁止出包与直传微信、站内管理页写操作禁用（可读可改草稿的例外见 §五）。 |
| 存量数据 | **默认已启动**，并进入固定 N 天免费过渡期（管理员可配，缺省 15 天）；过渡期内不出账，页面持续提示截止日与之后的单价。 |
| 计费口径来源 | 唯一真源＝平台管理员在 `/admin/points → 价目与用量` 配置的行；启动页文案由后端 `billingNote()` 用**出账同一个函数**渲染，不存在两张嘴。 |
| 支持的口径 | 免费 / 按日 / 按 30 天 / 按年（周期预付）+ 按访问 / 按流量（**本期只计量不出账**）。 |
| 欠费 | 续扣余额不足 → 账单 `ARREARS` + 起算宽限（缺省 72h，管理员可配）；超期转停服（等同未启动，`stopReason=ARREARS`）；数据一律不删；充值后日批补扣并自动复活、账期顺延。 |
| 国际独立站 | 保留**现有站点级自然月账单**（`geo_site_bills`）不动，避免改变已上线的扣费口径；它的「启动」只做功能闸与账期联动——订阅停止期间不再产生新月账。 |

## 二、数据（迁移 `0142_tool_launch_billing`）

1. `module_pricing` 增列（ additive，老行默认空串＝沿用原语义）：
   - `billing_cycle VarChar(16) DEFAULT ''`：`''`(沿用 METERED 用量) / `FREE` / `DAY` / `DAY30` / `YEAR` / `USAGE_PV` / `USAGE_BYTES`；
   - `usage_unit_size Int DEFAULT 1`（按量口径的计量粒度，如「每 1000 次访问」＝1000，本期只展示）；
   - `launch_enabled TinyInt DEFAULT 1`（是否允许用户自行启动，关掉＝该平台板块只给存量）。
2. `tool_subscriptions`（启动台账，`@@unique([userId, toolCode])`）：
   `status`（`STOPPED` / `TRIAL` / `ACTIVE` / `ARREARS`）、`startedAt` / `stoppedAt`、
   `cycleDays` 与 `unitPriceAmount`（**启动时快照**，管理员改价下期生效，避免账期内变价说不清）、
   `periodStart` / `periodEnd`、`billedPeriods`、`trialEndsAt`、`arrearsSince`、
   `stopReason`（`NOT_STARTED` / `USER` / `ARREARS` / `PLATFORM`）、`offBy` / `offReason`。
3. `tool_subscription_bills`（周期账单）：
   `periodKey`（周期起点 ISO 秒）+ `@@unique([subscriptionId, periodKey])` 双保险幂等（照搬 `geo_site_bills`），
   `billingMode` / `days` / `quantityAmount` / `unit` / `pointsAmount` / `status`（`CHARGED|WAIVED|ARREARS`）/ `txId`。
4. `tool_usage_daily`（本期只计量）：`@@unique([userId, toolCode, day])` + `pv Int` + `bytes BigInt`。

`toolCode` 直接用功能目录里的卡片码：`knowledge-pay` / `onsite` / `brand-mall` / `health` / `marketplace` / `digital-human` / `card-shop` / `kuaidi` / `global-site`；价目行 `pricingCode` 用下划线码（`knowledge_pay` … `geo_site`），映射表在新模块的 catalog 里单点维护。

## 三、后端新模块 `backend/src/tool-launch/`

| 文件 | 职责 |
| --- | --- |
| `tool-launch.catalog.ts` | 9 工具目录：toolCode ↔ pricingCode ↔ featureCode ↔ 管理端前缀 ↔ C 端前缀 ↔ 中文名 / 一句话说明 / 站点基数。 |
| `tool-launch.service.ts` | `states(userId)`（列表页与横幅共用）、`detail`、`start`（校验余额 → 首期预付 → 落订阅）、`stop`、`viewOf(toolCode,userId)`（带 30s 内存缓存与显式失效，供 C 端高频读）、`requireStarted`。 |
| `tool-launch.pricing.ts` | **纯函数**：`resolvePlan(pricingRow)` → 人话口径（周期、单价、免费额、起扣、宽限、过渡期）；`periodOf(anchor, cycleDays, now)` → 账期键/起止/折算天数。展示、启动确认、出账三处共用。 |
| `tool-launch.billing.service.ts` | `runDaily`（`system_settings.last_tool_launch_batch_date` 守卫，月中断不落守卫键）、`renewDue`（到期续扣）、`settle`（`debitTx` + 账单 + `usageEvent` 同事务，幂等键 `tool_launch:{toolCode}:{subId}:{periodKey}`）、`sweep`（欠费超宽限停服 / 补扣复活 / 过渡期到期转首期）。 |
| `tool-launch.scheduler.ts` | 每小时 tick，仿 `geo-site.scheduler.ts`，`TOOL_LAUNCH_SCHEDULER_DISABLED` 可关。 |
| `tool-launch.gate.ts` | 管理端中间件：路径前缀 → toolCode；**只拦写**（POST/PUT/PATCH/DELETE），`/enterprise/tool-launch`、`/enterprise/points`、`/enterprise/account`、`/enterprise/admin` 恒放行；未启动抛 `TOOL_NOT_STARTED`（带 `startUrl`）。 |
| `tool-launch.meter.ts` | C 端计量：公开响应回来后累加 `pv/bytes`，任何异常静默（不阻断业务），只写当日行。 |
| `tool-launch.controller.ts` | `ToolLaunch_*`（`states/detail/start/stop/bills/usage`）与 `ToolLaunchAdmin_*`（`settings/saveSettings/offline/online/bills`）。 |

C 端接入方式：各工具公开通道**已经**在解析站点行并判自家 `status`（见调研），只在解析出 `ownerUserId` 之后加一句 `await toolLaunch.blockIfStopped('brand-mall', shop.ownerUserId)`，返回该工具**现有的停服响应形状**——不改 9 个小程序模板，避免端上一起发版。

出包/直传接入：8 个 `*.release.service.ts` 与 `kp.package.ts` 的入口统一 `requireStarted`（错误文案给出启动页链接）。

- 契约 `packages/contracts/src/tool-launch.ts`：`mpToolLaunchStateSchema`、`mpToolLaunchDetailSchema`（含 `plan` 结构化计费口径 + `planText` 一句话）、`mpToolBillSchema`、`mpToolUsageSchema`、管理员设置 schema。

## 五、前端

1. `/site-builder` 每张卡片加状态徽标：`未启动`（灰）/ `免费过渡期至 M-D`（蓝）/ `运行中 · 下期 M-D 扣 N`（绿）/ `欠费宽限中`（橙）/ `欠费停服`（红），卡片右下「启动设置」入口。
2. 新页 `/site-builder/launch?tool=<code>`（**启动设置页**）：
   - 状态条：当前状态、本期起止、下期扣费日、账期快照单价、余额与不足提示（不足时给「去充值」）；
   - **计费规则卡**：完全渲染后端 `plan`（模式、周期、单价、免费额、起扣额、宽限小时、过渡期截止），按访问/流量口径额外显示「当前只计量、暂未出账」；
   - 用量卡：本期 PV / 流量（本期只读）；
   - 账单台账：最近账单（`已扣费 / 免费额内 / 欠费待补`）；
   - 启动确认弹层必须逐条讲清：启动即扣 X 积分、之后每 Y 天自动续扣、余额不足宽限 Z 小时后停服、数据保留。
3. 各工具首页/设置页顶部嵌 `<ToolLaunchBanner tool="brand-mall" />`：未启动/欠费停服时红条 + 「立即启动」；写操作被 403 时全局错误处理跳启动设置页。
4. 平台后台 `/admin/points → 价目与用量`：9 个工具行的「计费口径」下拉（免费 / 按日 / 按 30 天 / 按年 / 按访问 / 按流量）+ 单价 + 免费额 + 起扣 + 是否允许自启；同页上方加全局「欠费宽限小时 / 存量免费过渡天」。`billingSubjectLabel` 补 9 个工具中文名。

## 七、风险与红线

1. **不能在闸门里误伤计费与账号自救路径**：`/enterprise/points`（充值）、`/enterprise/account`、`/enterprise/tool-launch` 必须恒放行，否则欠费用户无法充值复活。
2. **账期快照**：订阅行必须固化启动时的 `cycleDays`/`unitPrice`，出账只读快照；管理员改价只影响下一期，页面要写「新价自 X 起生效」。
3. **幂等三保险**：`point_transactions.idempotencyKey` 唯一 + `tool_subscription_bills (subscriptionId, periodKey)` 唯一 + 日批守卫键；`isUniqueViolation` 必须同时认 P2002 与 PG `23505`。
4. **双库**：周期推进用条件更新（`updateMany({ id, periodEnd: 原值 })`）代替行锁；`bytes` 用 `BigInt`，聚合时转字符串再换算，避免 JS 精度丢失。
5. **geo-site 不双扣**：新闸门对 `global-site` 只做功能闸与「停止期间不产生新月账」，绝不与 `geo_site_bills` 并行走一套新账单。
6. **过渡期默认值**：上线迁移把存量账号的 9 个工具置 `TRIAL`（`trialEndsAt = 上线日 + transitionDays`），而不是 `STOPPED`——否则上线当天就打掉正在营业的店铺。

**与原方案的差异**

1. 状态机落成 `STOPPED / TRIAL / ACTIVE / ARREARS` + `stopReason`（`NOT_STARTED|USER|ARREARS|PLATFORM`），未另开 `offBy` 之外的快照字段。
2. C 端**不抛 403**：改用各工具已有的停服响应形状，9 个小程序模板零改动、不必跟着发版。
3. 国际独立站：`start` 与日批都不出周期账；改为 `GeoSiteBillingService.chargeMonth` 过滤掉 `global-site` 已显式 STOPPED 的账号（缺行照常出账，避免老账号白停一月）。
4. 免费额语义按口径分流：周期口径＝启动后前 N 期免费；按访问 / 按流量＝每期免费量。
5. 计量字节只对 JSON 响应取长度，图片与代码包这类大响应按 0 计（克隆响应纯粹浪费内存），出账前会换成网关口径。
6. 子账号可以停止工具（不产生扣费），但不能启动——启动会立即扣主账号积分。

**扣费状态机细则（2026-11-19 复核后定稿，实现点唯一）**

| 场景 | 行为 | 实现点 |
| --- | --- | --- |
| 用户主动停止（`stopReason=USER`）后仍挂着欠费单 | 日批**不补扣也不重新开机**；欠费单留着，等用户自己点「启动」时先结清再恢复 | `resumeArrearsBill()` 非交互路径只认 `ARREARS` / `stopReason=ARREARS` |
| 平台人工停用（`offBy` 非空） | 日批不补扣；用户点「启动」直接拒绝并提示联系平台客服，只有平台后台「强制启用」能解除 | `resumeArrearsBill()` 开头短路 + `start()` 抛 FORBIDDEN |
| 宽限期里点「启动」 | 走**补欠那一期**，不另起新周期（否则同一段时间付两次）；余额不足当场报「欠费待补 + 充值入口」 | `start()` 先 `resumeArrearsBill(interactive=true)`；`sweep()` 复用同一函数 |
| 停止后在已付账期内再启动 | 只重开功能闸并沿用剩余账期，**不再收一期**（不动 `billedPeriods`、不新增账单） | `start()` 的 `paidWindowOpen` 分支 |
| 存量免费过渡期内停止后再启动 | 回到 `TRIAL` 并保留 `trialEndsAt`，**一期都不扣**，到期仍由日批转正出首期 | `start()` 的 `trialWindowOpen` 分支 |
| 账期确实已到期后再启动 | 照常按当期口径预付新一期（复用分支不许把该收的免掉，有专门用例锁这条） | `start()` 主路径 |
| 并发双击 / 日批跑挂后隔天重跑 | 幂等键＝`P{第几期}`（由库里持久计数推导，与请求时刻无关）→ 撞 `(subscriptionId, periodKey)` 唯一索引，第二次只会被当成「已出过账」 | `periodKeyOf(periodNo)`；`periodOf()` 只算起止日期 |
| 过渡期到期转正 | 账期锚点＝`trialEndsAt`，不是「日批跑到这一行的那一刻」 | `promoteTrials()` |
| 出账失败（余额不足） | 账单落 ARREARS + 订阅进 ARREARS + 积分账户标 ARREARS（充值后由积分侧自动清回 ACTIVE，与 `chargeSafely` 同口径） | `settlePeriod()` ARREARS 分支 |
| 启动页「下次扣费 / 余额是否够」 | 与 `chargeForPeriod` 同源；ownBilling（国际独立站）恒显独立站月账说明，不显示周期扣费 | `view()` + `planOf()` / `ownBillingNote()` |

**本期未完成**：按访问 / 按流量出账（计量已在累计，出账开关闭合，失败请求已不计入 PV/流量）；国际独立站停服过滤已有用例（`geo-site.billing.pause.spec.ts`），但退款异步对账仍缺路由——见执行方案 §七「仍未做」。

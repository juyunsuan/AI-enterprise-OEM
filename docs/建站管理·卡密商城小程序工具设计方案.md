# 建站管理 · 卡密商城小程序工具 设计方案

> 状态：设计定稿，待逐条授权实现。

## 一、产品口径（已与需求方确认的四项决策）

| 决策点 | 结论 | 与鲸发卡的差异 |
| --- | --- | --- |
| 资金 | **用户自填微信支付商户号（APIv3 直连）**，钱直接进店主自己的商户号，平台不经手、不记账 | 鲸发卡是「平台聚合通道 `channel` + 商户余额 `money`/`freeze_money` + 提现 `cash`/代付 `cash_channel`」的资金归集模式。本方案**没有平台侧资金账本、没有提现与代付链路**，只有订单支付状态 |
| 首期范围 | **核心交易闭环**：站点 + 分类 + 卡密商品 + 卡密批次导入/回收站/导出 + 匿名下单 + 微信支付 + 即时出卡 + 查单取卡 + 优惠券 + 公告/文章/单页 + 装修开关 + 出包直传微信 | 商户注册与多商户入驻、商品代理（`proxy`/`agent_key`）、跨平台代下（`cross`）、共享卡池（`goods_pool`）、付费挑卡（`selectcard`）、费率组（`rate_group`）、投诉工单、微信服务号粉丝运营、云打印 → 全部列入二期及以后（见 §十） |
| 买家身份 | **匿名下单 + 可选微信登录**：联系方式（手机/邮箱/QQ，按商品要求）+ 取卡密码即可查单取卡；`wx.login` 登录后有「我的订单」 | 鲸发卡纯匿名，只有「查单页」。本方案复用私域底座的顾客令牌，让 C 端有订单历史，不新造身份体系 |
| 小程序端 | **新建独立原生小程序模板 `card-shop-miniprogram/`**，按本项目规范补齐（参考源码只有 H5/PC 端，无小程序） | 净新增能力 |
| 在线客服 | **直接复用系统 AI 客服（`service-desk` 服务站）**：站点绑定店主自己的 `siteKey`，小程序「客服」页用 `web-view` 打开现成 H5 页 `/embed/service-desk?key=…`，本业务不写一行客服代码 | 鲸发卡是「服务号粉丝 + 模板消息 + 商家微信/QQ 名片」的自有客服链路。本方案改为挂到平台 AI 客服底座上：店主在「AI 客服」里配好的机器人、知识库、人工坐席与工作时间，卡密商城小程序天然继承；未绑定服务站时降级为联系方式名片 |
| 业务隔离 | 数据、订单、顾客与 mall / knowledge-pay / onsite **完全隔离**；只共享「机制底座」（凭据、出包、顾客令牌、OSS），不共享任何业务表 | 关本板块只拦 `/enterprise/card-shop/**`，其他板块零影响 |

一句话产品定义：**每个本站用户都能开一个属于自己的卡密（虚拟卡/兑换码）自动发货微信小程序商店——传卡密、挂商品、收自己的钱、买家付款即时拿卡，代码包一键传进自己的微信账号。**

## 三、数据模型（首期 11 张表）

### 3.1 租户与配置

**`card_shop_sites`（站点实例，一个账号一家店）**

| 字段 | 说明 |
| --- | --- |
| `id` / `ownerUserId` | 归属本站账号（= 店主） |
| `enterpriseId` / `enterpriseUserId` | 企业档案留痕，与 `MallShop` / `GeoSite` 同口径 |
| `siteCode` | 公开寻址码（唯一，8 位去混淆字母表），小程序 `config.js` 的 `site` 值，创建后不变 |
| `name` / `logo` / `slogan` / `themeColor` | 品牌与主题（打包注入 + 服务端 `/bootstrap` 可覆盖） |
| `notice` | 首页滚动公告文案（与公告列表分开，轻量常驻） |
| `deskSiteKey` | **在线客服指向**：店主在「AI 客服」建的服务站 `siteKey`（`ServiceDesk_sites` 可选值，绑定时服务端校验归属，不许绑别人的）；空 = 未启用在线会话 |
| `serviceContact` | 联系方式兜底 JSON：`{ phone, qq, wechat, email }`——未绑服务站时小程序展示它，绑了服务站则作为会话页底部次要入口 |
| `toggles` | 模块显隐 JSON：`indexBanner / indexNotice / indexHot / categoryPage / search / coupon / protocol / article / deskChat / contact / myOrders`（沿用 `KnowledgePaySite.toggles` 口径；`deskChat` 控制在线客服入口显隐，关掉后只留联系方式） |
| `stockDisplayMode` | 库存展示：`ACTUAL` 实际数字 / `RANGE` 分段（充足·紧张·售罄），对应源码 `stock_display` |
| `cardOrderMode` | 出卡顺序：`OLDEST`（先卖老卡）/ `NEWEST`（先卖新卡）/ `RANDOM`，站点默认，商品可覆盖 |
| `protocolContent` | 购卡协议富文本（买家下单前必须勾选，对应源码 `shop_gouka_protocol_pop`） |
| `status` | `DRAFT`（未上线）/ `ONLINE`（营业中）/ `CLOSED`（店主关店，数据保留）；历史 `SUSPENDED` 仅存量数据 |
| `createdAt` / `updatedAt` | — |

> 微信凭据**不落本表**：一律 `miniprogram_apps`（`scene='CARD_SHOP' + shopId=siteId`），出包台账走 `miniprogram_tenant_releases`。这是相对 knowledge-pay（早期把 `wxAppId/wxAppSecret/wxUploadKey` 内嵌在站点表里）的收敛，与电商/上门一致。

**`card_shop_platform_settings`（平台侧单行配置）**
`goodsQuota`、`cardQuota`（单站卡密上限）、`importMaxLines`（单次导入行数，默认 5 万）、`importMaxBytes`、`payAllowed`（是否下发在线收款通道）、`enabled`（全站开关）、`keywordFilter`（商品名/说明敏感词，逗号分隔）。

### 3.2 商品域

**`card_shop_categories`**：`siteId`、`title`、`cover`、`icon`、`sort`、`status`。

**`card_shop_goods`（卡密商品，一个商品 = 一种卡的一批库存）**

| 字段 | 对应源码 | 说明 |
| --- | --- | --- |
| `id`/`siteId`/`categoryId` | `goods.user_id/cate_id` | 归属 |
| `name` / `cover` / `images` | `goods.name` | 标题与图（图走 OSS） |
| `price` | `goods.price` | 单价（元，DECIMAL(12,2)） |
| `wholesaleTiers` | `wholesale_discount` + `wholesale_discount_list` | 批发阶梯价 JSON：`[{ min, price }]`，为空即不启用 |
| `limitQuantity` / `maxQuantity` | `limit_quantity` / `max_quantity` | 起购 / 单笔限购（0 = 不限） |
| `stockWarn` | `inventory_notify` | 库存预警阈值（0 = 不预警），命中后站内信 + 可选邮件提醒店主 |
| `couponEnabled` | `coupon_type` | 是否允许用券 |
| `takeCardMode` | `take_card_type` | 取卡密码：`OFF` / `REQUIRED` / `OPTIONAL` |
| `visitPassword` | `visit_password` | 访问密码（空 = 关闭；加密存储，命中后站点级短时放行） |
| `contactMode` | `contact_limit` | 买家必填联系方式：`ANY` / `MOBILE` / `EMAIL` / `QQ` / `NONE` |
| `notifyFlags` | `sold_notify` / `email_notify` | 售出通知 JSON：`{ merchantStation: true, buyerEmail: false }`（短信与服务号模板消息二期） |
| `cardFormat` | `split_type` 的展示侧 | 卡密形态：`SINGLE`（只有卡密）/ `PAIR`（卡号+卡密）——决定详情页与取卡页渲染 |
| `intro` / `content` / `remark` | `content` / `remark` | 简介 / 图文详情（富文本，走净化） / 使用说明（取卡后展示，如「去 xxx 兑换」） |
| `cardOrderMode` | `card_order` | 覆盖站点默认出卡顺序 |
| `hot` / `sort` / `viewCount` / `soldCount` | `sort` 等 | 展示与统计 |
| `status` | `status` + `is_freeze` | `DRAFT` / `OFFLINE` / `ONLINE` / `FROZEN`（平台风控冻结） |
| `trashedAt` | `delete_at` | 软删（回收站可恢复） |

### 3.3 卡密域（本业务的核心资产）

**`card_shop_card_batches`（导入批次台账，可整批撤销）**
`siteId`、`goodsId`、`batchNo`（`CSB` + 时间戳 + 随机，唯一）、`source`（`TEXT` / `FILE`）、`splitter`（本次识别的分隔符）、`totalLines`、`importedCount`、`duplicatedCount`、`invalidCount`、`orderMode`（顺序/乱序）、`operator`、`createdAt`。

**`card_shop_cards`（卡密本体）**
`siteId`、`goodsId`、`batchId`、`number`（卡号，`SINGLE` 形态存空串）、`secret`（卡密）、`status`：`AVAILABLE` / `LOCKED`（已被未支付订单占用）/ `SOLD`（已售出）/ `DISABLED`（人工停用）/ `VOID`（作废）；`lockOrderId`、`lockExpireAt`、`soldOrderId`、`soldAt`、`soldIp`、`seq`（导入序号，`OLDEST/NEWEST` 出卡依据）、`remark`、`trashedAt`（回收站）。
索引：`@@index([siteId, goodsId, status, seq])`（出卡主查询）、`@@index([siteId, batchId])`、`@@unique([siteId, goodsId, number, secret(191)])` 兜底去重。

### 3.4 交易域

**`card_shop_orders`（订单）**
`siteId`、`orderNo`（复用单号器，前缀 `CS`，`CS + yyyyMMddHHmmss + 6 位随机`，唯一）、`goodsId`、`goodsName`/`goodsCover`/`unitPrice`/`cardFormat` 快照、`quantity`、`productAmount`、`discountAmount`、`couponId`、`totalAmount`（实付）、`contact`、`email`、`takeCardPasswordHash`（bcrypt/SHA-256，明文不落库）、`payState`：`PENDING` / `PAID` / `CLOSED` / `REFUNDED` / `FAILED`、`transactionId`（微信流水）、`paidAt`、`closedAt`、`refundedAt`、`cardCount`（已出卡数）、`customerId`（0 = 匿名）、`openid`、`createIp`、`userAgent`、`expireAt`（未支付锁卡到期时间，默认 15 分钟）、`failReason`。
索引：`@@unique([siteId, orderNo])`、`@@index([siteId, payState, createdAt])`、`@@index([siteId, contact])`（查单）、`@@index([customerId])`。

**`card_shop_order_cards`（出货快照，与卡密本体解耦，卡被删除也不影响历史订单取证）**
`orderId`、`cardId`、`number`、`secret`、`sort`、`createdAt`。`@@index([orderId])`。

### 3.5 顾客与营销

**`card_shop_customers`（C 端顾客，openid 维度，与站内 `User` 物理隔离）**
`siteId`、`openid`（`@@unique([siteId, openid])`）、`unionid`、`nickname`、`avatar`、`orderCount`、`lastOrderAt`、`status`、`createdAt`。

**`card_shop_coupons`（券码，一码一用）**
`siteId`、`code`（`@@unique([siteId, code])`）、`kind`：`FIXED`（减额）/ `PERCENT`（折扣，`value` 为 1–99 表示百分比）、`value`、`categoryId`（0 = 全部分类）、`minAmount`（满多少可用，源码缺此项，补齐）、`expireAt`、`status`：`UNUSED` / `LOCKED` / `USED` / `DISABLED`、`usedOrderId`、`usedAt`、`batchNo`（批量生成）、`remark`。

### 3.6 内容

**`card_shop_contents`（公告 / 文章 / 单页三合一）**
`siteId`、`kind`：`NOTICE`（首页公告栏，可弹窗）/ `ARTICLE`（资讯列表）/ `PAGE`（单页：关于我们、联系我们、帮助）、`title`、`summary`、`content`（富文本）、`cover`、`images`、`link`、`sort`、`popAuto`（自动弹出）、`status`、`createdAt/updatedAt`。

> 首期表数 **11 张**（源码 89 张里，只有这些进入核心闭环；其余是资金、代理、插件、服务号与站内后台脚手架）。

## 四、后端结构

```
backend/src/card-shop/
  card-shop.shared.ts           // scene 常量、siteCode/orderNo、金额分↔元、JSON 归一化、状态枚举回落
  card-shop.service.ts          // 站点 CRUD、看板统计、协议与开关、平台设置读写
  card-shop.goods.service.ts    // 分类 + 商品（含回收站、批量上下架、库存预警）
  card-shop.card.service.ts     // ★ 卡密：文本/文件导入解析、去重、乱序、批次台账、编辑、导出、回收站与还原
  card-shop.order.service.ts    // ★ 交易：下单锁卡（原子）、支付成功后出货、关闭释卡、查单取卡、对账兜底
  card-shop.coupon.service.ts   // 券码生成、校验、锁定/核销/退回
  card-shop.customer.service.ts // wx.login code2session 建档、我的订单
  card-shop.pay.service.ts      // 微信支付 APIv3（JSAPI + 回调验签解密），凭据来自 MiniAppService.payRuntime
  card-shop.release.service.ts  // 按站注入出包 + miniprogram-ci 直传 + 版本台账（复用 private-mini）
  card-shop.notify.service.ts   // 售出/库存预警通知（站内信，邮件复用 aliyun-mail）
  card-shop.scheduler.ts        // 过期未支付订单关单释卡、锁卡回收（对齐 mall.scheduler.ts 注册方式）
  card-shop.controller.ts       // CardShop_* 派发（moduleHandlers 自动接线，返回值不套信封）
  card-shop.admin.controller.ts // CardShopAdmin_* 平台侧
  card-shop.public.ts           // /api/public/card-shop/**（手写注册，不进 JSON 契约与 OpenAPI）
```

装配点：`backend/src/http/services.ts` 实例化各 service + controller 并挂到 `cardShop` 命名空间；`backend/src/http/automation-routes.ts` 增 `moduleHandlers('CardShop_', c.cardShop.controller)` 与 `'CardShopAdmin_'`；`backend/src/http/app.ts` 增 `registerCardShopPublic`。改 `contracts` 后必须重新构建并 `pnpm api:docs` 生成 `docs/api/openapi.json`（CI `api:docs:check` 逐字节比对）。

## 六、卡密交易的两个硬问题（实现重点，也是评审重点）

### 6.1 原子锁卡（双库一致）

不能「先查后改」——并发下会超卖同一张卡。做法：
1. 按 `cardOrderMode` 取候选 id（`OLDEST` 用 `seq asc`、`NEWEST` 用 `seq desc`、`RANDOM` 用 `RAND()/random()` 走方言分支）；
2. 条件更新收口：`UPDATE card_shop_cards SET status='LOCKED', lockOrderId=?, lockExpireAt=? WHERE siteId=? AND goodsId=? AND status='AVAILABLE' AND id IN (...)`，**以 `affectedRows === quantity` 为准**，不足即整单事务回滚并返回「库存不足」；
3. 全程包在 `prisma.$transaction`；MySQL/PG 都走同一份 Prisma `updateMany` + 原生兜底，不用 `SELECT ... FOR UPDATE`（PG/MySQL 行为差异与连接占用）。
支付成功后把锁卡 `status → SOLD` 并写 `soldOrderId/soldAt`，同时把卡密内容复制到 `order_cards`；关单或 `lockExpireAt` 到期由 `card-shop.scheduler.ts` 释放回 `AVAILABLE`（源码里靠 `auto_unfreeze` 表 + 定时任务，本方案用 `lockExpireAt` 索引扫描，不新增表）。

### 6.2 取卡凭证安全

- 取卡密码只存哈希（`SHA-256 + siteId 盐`），明文永不落库、不进日志、不出现在订单导出默认列；
- 查单必须同时命中 `orderNo + contact`，若 `takeCardMode≠OFF` 再加取卡密码；三者任一不符统一返回同一句「订单信息不匹配」（不给枚举空间），并计入 `RateWindow`；
- 卡密明文只在「支付成功后的取卡页 / 店主订单详情」两处返回，接口响应不缓存（`Cache-Control: no-store`）。

## 十、已识别风险与二期边界

1. **灰产与合规**（最需盯的一条）：卡密类虚拟商品易被用于兑换码倒卖、洗钱通道。缓解——平台侧敏感词、跨店订单排查、下单 IP 限流、导出留痕，以及店主自己的关店与上下线；二期可加实名/保证金（`deposit_money` 在源码里已存在，本方案首期不做）。
2. **资金直收意味着平台无法担保交易**：买家纠纷只能引导联系店主，首期不做平台介入退款（微信商户号后台自行退款），文案要写清「款项由店主收取」。
3. **锁卡与订单一致性**：6.1 的 `affectedRows` 收口 + 事务是唯一的正确性支点，必须有并发测试兜底；不能用「库存数递减 + 卡池随机取」两步做（源码的 `goods_pool` 思路在双库下更难保证）。
4. **富文本与 XSS**：商品详情/使用说明/单页均走既有 HTML 净化（`purify` 口径）+ `contentKind` 一致性检查，小程序端 `rich-text` 不支持任意 HTML，需后端下发放行子集。
5. **导入文件体积**：单次导入行数上限与内存解析（按行流式，不整体 `split`），超限给明确提示而不是静默截断。
6. **出包注入点变更风险**：`private-mini/package-builder` 的模板目录当前按 scene 取源码目录，加 `CARD_SHOP` 分支时不得改动 MALL/ONSITE 已有映射；对应要补 `package-builder.spec.ts` 用例。
7. **小程序提审**：卡密/虚拟商品类目在微信侧属受限类目，模板文案避免出现「兑换码倒卖」「充值」等敏感词，提审类目与资质由店主自己在微信公众平台处理（与既有「提审发布在微信侧」口径一致）。
8. **客服走 web-view 的域名门槛**：`/embed/service-desk` 是 H5 页，小程序 `web-view` 要求把 apiBase 域名单独登记为**业务域名**（与 `request` 合法域名是两套清单），且该域名需在微信侧校验文件。发布页签要写清这一步，且 `deskChat` 开关旁给「客服不可用的两种原因」提示；未登记时小程序端回落联系方式卡片，不能白屏。另外客服会话归属于店主的 AI 客服账号，本模块不做会话数据二次存储。
9. **二期及以后明确不做**：聚合支付通道与商户余额/提现/代付、商户注册与邀请码分销（`invite_code`/`spread`/`ambassador`）、商品代理与全站代理（`proxy`）、跨平台代下（`cross`）、共享卡池与池授权（`poolauth`）、付费挑卡（`selectcard`）、费率组（`rate_group`）、投诉工单（`complaint`）、短信通知、服务号粉丝与模板消息、站点主题市场（`shopdiy`）。

# 指纹浏览器技术方案（内核路线 · 类比特浏览器）

> 目标：把 BotBuddy 客户端扩展为「指纹浏览器管理器 + Agent 宿主」。每个指纹窗口 = 独立的改造版 Chromium 内核进程（独立用户目录 + 独立指纹 + 独立代理出口），最多 100 个窗口；浏览器页两个 Tab（指纹窗口 / Chrome 插件）。交互对齐比特浏览器（BitBrowser）。

---

## 1. 路线结论

- **采用比特浏览器的技术路线：内核级指纹**。不再用 Electron 自带 Chromium 做指纹窗口（应用层注入无法覆盖 TLS/JA3、深层字体/协议、扩展完整能力）。
- 客户端角色变为**管理器**：
  - 管理指纹档案（最多 100 个）、代理、扩展、内核版本；
  - 为每个窗口拉起一个**独立的指纹内核进程**（独立 `--user-data-dir`），并管理其生命周期；
  - 对 Agent 暴露统一的浏览器工具（CDP 驱动），对外提供可选本地 API。
- 已确认的决策（第 15 节）：100 为**存储上限**、并发默认 20 可配 100；代理 HTTP/HTTPS/SOCKS5（账号密码 + IP 白名单）；Canvas/Audio 默认轻噪 + 稳定种子、WebGL 模板；Agent **显式绑定默认窗口**；IP 检测默认 ipify 可配。
- 诚实边界：内核路线能把指纹风险收敛到与比特浏览器同一级别，但**不存在"绝对不可检测"**；出口 IP 质量、账号行为、内核版本时效仍是主要变量（第 14 节）。

## 2. 总体架构

```
┌──────────────────── Renderer（浏览器页 · 两 Tab） ───────────────────┐
│  指纹窗口：列表 / 新增 / 编辑 / 打开 / 关闭 / 代理 / 内核版本          │
│  Chrome 插件：上传 ZIP·文件夹 / 列表 / 删除 / 按窗口启用               │
└──────────────────────────────▲──────────────────────────────────────┘
                               │ IPC（fp:* / chromeExt:* / localApi:*）
┌──────────────────────────────┴──────────────────────────────────────┐
│                          BotBuddy Main（管理器）                      │
│  fp/profiles.js    档案 CRUD、100 上限、默认窗口、AES 加密代理凭据     │
│  fp/fingerprint.js 种子/覆盖项 → 内核启动参数与一致性校验              │
│  fp/kernels.js     内核安装/版本/哈希校验/路径解析                     │
│  fp/proxy-relay.js 本地认证转发（HTTP CONNECT / SOCKS5 上游 + 白名单）  │
│  fp/launch.js      每个窗口一个内核进程：user-data-dir/端口/扩展/参数   │
│  fp/cdp.js         CDP 客户端（tabs/navigate/read/click/fill）         │
│  fp/local-api.js   可选本地 HTTP API（127.0.0.1，token）               │
│  builtin-browser.js（退役为兜底，不含指纹）                            │
│  chrome-extensions.js（沿用，扩展目录管理）                            │
└──────────────────────────────▲──────────────────────────────────────┘
                               │ spawn / CDP / SQLite
┌──────────────────────────────┴──────────────────────────────────────┐
│  指纹内核进程 × N（改造版 Chromium）                                  │
│    kernel/chrome.exe                                                  │
│      --user-data-dir=~/.botbuddy/fp-profiles/<id>                     │
│      --fingerprint=<seed> --fingerprint-platform=... ...              │
│      --proxy-server=http://127.0.0.1:<relayPort>                      │
│      --remote-debugging-port=<cdpPort> --load-extension=...           │
└─────────────────────────────────────────────────────────────────────┘
```

关键变化：

- **窗口 UI 用内核自带浏览器窗口**（地址栏/前进后退/标签页都是原生 Chrome），不再由 Electron 画工具栏；
- Electron 只负责管理台与 Agent；关闭管理器时按策略回收内核进程；
- Agent 与外部自动化都通过 **CDP / 本地 API** 操作具体窗口，语义确定。

## 3. 内核选型与集成

### 3.1 候选

1. **fingerprint-chromium（开源，推荐起步）**：对 Chromium 做指纹补丁，支持种子（`--fingerprint=<seed>`）与平台/品牌等启动参数；Open-Anti-Browser、Ant-Browser 等项目已用它做同型产品。
2. **自维护补丁内核**：fork Chromium + 指纹补丁 + 版本升级流水线（成本最高，可控性最强）。
3. **商业授权内核**：直接采购，需评估许可与更新支持。

> v1 采用方案 1 先跑通"管理器 + 内核"骨架；后续按风控强度决定是否升级为 2/3。

### 3.2 内核目录与校验

```
~/.botbuddy/kernels/
  <version>/                # 每个内核版本一个目录
    chrome.exe
    manifest.json           # {version, platform, sha256, source, license}
```

- 安装包内置一个 Windows x64 主版本；更多版本（如旧系统指纹用的 104 内核）按需下载或随包分发；
- 启动前校验 `manifest.json` 的 sha256；只允许从受管目录启动；
- 版本选择：全局默认 + 按 profile 覆盖（对齐比特浏览器的多内核形态）。

### 3.3 指纹参数（按内核协议下发）

- 主参数：`--fingerprint=<seed>`（同一 seed 跨重启稳定复现）；
- 覆盖项：平台/品牌/屏幕/时区/语言等按内核支持的启动参数下发（具体开关以内核 manifest 声明的能力为准，管理器做能力探测与降级提示）；
- 缺参不臆造：内核不支持的指纹项在 UI 中置灰并注明"当前内核不支持"。

### 3.4 扩展能力

- 内核支持 `--load-extension=<dir1,dir2,...>`（未打包扩展），且是完整 Chromium，可覆盖 MV2/MV3；
- 扩展来源：`~/.botbuddy/chrome-extensions/<id>/`（沿用现有上传 ZIP / 文件夹 / 删除管理）；
- 按窗口启用：启动参数里只带启用的扩展目录；Chrome 插件 Tab 与窗口编辑页均可勾选。

## 4. 数据模型（本机 SQLite）

```sql
CREATE TABLE IF NOT EXISTS fp_profiles (
  id                    TEXT PRIMARY KEY,
  name                  TEXT NOT NULL,
  group_name            TEXT NOT NULL DEFAULT '',
  seed                  TEXT NOT NULL,
  kernel_version        TEXT NOT NULL DEFAULT '',   -- '' = 使用默认内核
  platform              TEXT NOT NULL DEFAULT 'win', -- win/mac/linux 指纹平台
  ua                    TEXT NOT NULL DEFAULT '',    -- 空 = 内核按 seed 生成
  screen_width          INTEGER NOT NULL DEFAULT 0,  -- 0 = 内核按 seed 生成
  screen_height         INTEGER NOT NULL DEFAULT 0,
  timezone              TEXT NOT NULL DEFAULT '',
  languages_json        TEXT NOT NULL DEFAULT '[]',
  canvas_noise          TEXT NOT NULL DEFAULT 'light',  -- off/light/strict
  audio_noise           TEXT NOT NULL DEFAULT 'light',
  webgl_mode            TEXT NOT NULL DEFAULT 'template', -- template/real
  webrtc_mode           TEXT NOT NULL DEFAULT 'proxy',   -- proxy/disable/real
  hardware_concurrency  INTEGER NOT NULL DEFAULT 0,
  device_memory         INTEGER NOT NULL DEFAULT 0,
  proxy_mode            TEXT NOT NULL DEFAULT 'direct',  -- direct/proxy
  proxy_type            TEXT NOT NULL DEFAULT '',        -- http/https/socks5
  proxy_host            TEXT NOT NULL DEFAULT '',
  proxy_port            INTEGER NOT NULL DEFAULT 0,
  proxy_auth_mode       TEXT NOT NULL DEFAULT 'password',-- password/whitelist
  proxy_user            TEXT NOT NULL DEFAULT '',
  proxy_password_cipher TEXT NOT NULL DEFAULT '',        -- AES-256-GCM（本机密钥）
  extra_args            TEXT NOT NULL DEFAULT '',        -- 高级启动参数（白名单校验）
  extension_ids_json    TEXT NOT NULL DEFAULT '[]',      -- 启用的 Chrome 插件 id
  last_open_at          TEXT,
  last_ip               TEXT,
  created_at            TEXT NOT NULL,
  updated_at            TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS fp_profiles_updated_idx ON fp_profiles(updated_at DESC);
```

规则：最多 **100 个档案**；同一档案同时只允许一个内核窗口；代理密码用 `~/.botbuddy/fp-secret.key`（AES-256-GCM）加密，界面只显示掩码；`extra_args` 只允许白名单开关，防止注入任意命令行。

## 5. 指纹一致性与自检

- 内核按 seed 生成一致的 UA / 屏幕 / WebGL / Canvas / Audio / 字体 / 时区等；管理器负责**跨维度一致性**：
  - 平台/UA/Client Hints/WebGL 模板配对（如 Windows + Direct3D11）；
  - 时区/语言 与出口 IP 国家一致（保存时代理检测后给出建议，不强制）；
  - 屏幕分辨率 ↔ 窗口尺寸 ↔ DPR；
  - WebRTC 策略：`proxy` → 启动时加 `--force-webrtc-ip-handling-policy=disable_non_proxied_udp`；`disable` → 停用非代理 UDP。
- **指纹自检页**（P3）：本地页面汇总当前窗口指纹 + 与档案配置比对，展示"实际值 / 期望值 / 是否一致"；附 WebRTC 候选、出口 IP、时区与 IP 地理位置对照。
- 不追求"随机越多越好"：同一档案稳定、内部自洽 > 过度随机。

## 6. 代理 / IP 绑定（本地认证转发）

### 6.1 为什么要本地转发

Chromium 的 `--proxy-server` 不支持在启动参数里带代理账号密码；直接给上游认证会触发客户端弹窗。管理器为每个打开窗口起一个**本地认证转发**：

```
内核 --proxy-server=http://127.0.0.1:<relayPort>
   → relay（本机，无鉴权）→ 上游 HTTP CONNECT / SOCKS5（带账号密码或 IP 白名单）
```

- 上游支持：`http` / `https`（CONNECT 隧道）/ `socks5`（含用户名密码握手）；
- **IP 白名单**模式：relay 不带凭据，直接连上游（依赖代理侧放行本机出口 IP）；
- 直连模式：不启 relay，内核直连（出口=本机 IP）；
- relay 只监听 `127.0.0.1` 临时端口，随窗口关闭回收；不记录流量内容。

### 6.2 出口 IP 检测

- 用档案配置（经 relay）请求可配置检测地址，默认 `https://api.ipify.org?format=json`；国内可配 `https://myip.ipip.net`；
- 返回 IP、耗时；可选地理信息（默认关闭），用于时区/语言建议；
- UI 显示：代理（直连｜http/socks5 host:port · 上次出口 IP）、检测按钮与错误原因（超时/认证失败/DNS 失败）。

### 6.3 DNS

- SOCKS5 上游使用远端解析（避免本地 DNS 泄漏）；HTTP 代理走 CONNECT 域名；
- 不使用 PAC；不做本地 hosts 改写。

## 7. 窗口生命周期与上限

- **档案上限 100**（存储）；**同时打开默认 20**（设置项可调，最大 100）；超出进入排队，UI 明示。
- 打开流程：分配 `cdpPort`（127.0.0.1 随机高位）与 `relayPort` → 启动内核 → 等 CDP 就绪 → 记录 PID/端口/状态 → 状态事件推送 UI。
- 关闭：先 `Browser.close`，超时再终止进程树；回收 relay；更新 `last_open_at`。
- 崩溃恢复：进程退出 ≠ 用户关闭时，标记"异常退出"，提供一键重开（同 seed、同 user-data-dir）。
- 管理器退出：按策略关闭所有内核窗口（默认关闭；可配置保留）。
- 资源监控：管理器汇总内核进程内存；超过阈值提示；支持「闲置 N 分钟自动关闭」（默认关闭）。

## 8. UI（浏览器页 · 两个 Tab）

### 8.1 Tab1 指纹窗口（默认）

- 头部：`新增窗口`、搜索/分组、`全部关闭`、刷新；计数「已用 x/100 · 打开 y/20」。
- 列表：名称/分组、内核版本、平台、屏幕、时区/语言、代理（类型 + 上次 IP）、状态（关闭/启动中/打开/排队/异常）、操作（打开·关闭 / 编辑 / 复制 / 删除）。
- 新增/编辑弹窗：
  - 基础：名称、分组、内核版本、指纹平台、屏幕、时区、语言；
  - 指纹：Canvas/Audio 噪声档、WebGL 模板、WebRTC 模式、`--fingerprint` 种子（可重新生成）；
  - 代理：直连 / HTTP(S) / SOCKS5；认证方式（账号密码 / IP 白名单）；host/port/账号/密码（留空=不改）；「检测 IP」；
  - 扩展：勾选本窗口启用的 Chrome 插件；
  - 一致性校验结果（阻断/建议）。
- 100 满时新增禁用并说明；删除需确认（可同时关闭窗口）。

### 8.2 Tab2 Chrome 插件

现有插件管理整体搬入：上传 ZIP / 选择文件夹、清单校验、列表、删除、打开插件目录；新增「按窗口启用」说明（在指纹窗口编辑页勾选）。

### 8.3 与 Agent 的关系

- **Agent 显式绑定「Agent 默认窗口」**（浏览器页可设置，默认取最近使用的档案）；不跟随鼠标焦点，避免用户切窗口干扰自动化；
- `chrome_tabs` 返回全部已打开窗口与 profileId/窗口 id；
- `chrome_open` 在绑定窗口内导航；必要时可在绑定档案上新建窗口；
- 旧的 Electron 内置单窗口浏览器退役为「兜底/普通浏览」，不再承担指纹窗口。

## 9. 本地 API（对齐比特浏览器）

- 管理器在本机 `127.0.0.1:54345` 提供 HTTP API（token 鉴权，默认关闭，可在设置开启并生成 token）；
- 端点（v1 最小集）：
  - `GET /health`
  - `GET /window/list`（含状态、profileId、wsEndPoint）
  - `POST /window/open`（profileId → 启动并返回 `wsEndPoint` / CDP 端口）
  - `POST /window/close`
  - `POST /proxy/check`
  - `GET /cookie/list|set|clear`（经 CDP）
- 仅监听回环；token 不进日志；与 Agent 工具共用同一套 `fp/*` 服务层。

## 11. 安全与合规

- 内核与扩展只从受管目录启动，启动前 sha256 校验；`extra_args` 白名单；本地 API 默认关闭、token 鉴权。
- 代理密码本机加密，不落日志、不向平台上报；所有数据与本机浏览器目录隔离在 `~/.botbuddy`。
- 内核分发遵循 Chromium/上游项目的许可证（保留 LICENSE/NOTICE），二进制与版本来源可追溯；商业使用时做合规评审。
- 仅用于合法用途：自有账号多环境隔离、已授权测试、隐私保护；不包含绕过验证码、风控或欺诈能力。

## 12. 验收标准

功能：

- 两 Tab；100 档案上限与并发上限/排队生效；新增/编辑/复制/删除/打开/关闭可用。
- 每窗口独立 `user-data-dir`：Cookie/存储互不串；同 seed 重开指纹一致；不同档案指纹不同。
- 代理：直连=本机 IP；HTTP/HTTPS/SOCKS5 经本地转发生效（出口 IP 与绑定一致）；账号密码与 IP 白名单两种上游都能工作；认证失败有明确提示。
- 扩展：上传/删除；窗口启动仅加载勾选扩展；MV2/MV3 由内核支持情况决定并如实提示。
- Agent：绑定窗口明确；`chrome_open/read/click/fill` 生效且不受用户切窗口影响。
- 本地 API（开启后）：open 返回可连的 wsEndPoint；close/list 正常。

质量：

- 单测：种子稳定性、一致性校验、100 上限、代理 relay（HTTP CONNECT/SOCKS5 握手与认证）、CDP 客户端、扩展目录。
- 现有 `npm run check` 全绿；安装包升级流程不变；内核随包分发（或按需下载 + 哈希校验）。

## 13. 里程碑

- **P1 内核骨架（约 5–7 天）**：内核接入与校验、档案 CRUD、代理 relay、单窗口启动、CDP 工具、浏览器页 Tab1 基础管理。
- **P2 规模化与联动（约 4–5 天）**：多窗口/并发上限/排队/崩溃恢复、Agent 绑定默认窗口、扩展按窗口启用、Tab2 融合。
- **P3 增强（约 4–5 天）**：本地 API、指纹自检页与泄漏检测、代理池/批量分配、分组/导入导出、Cookie 管理、闲置自动关闭。
- **P4 内核纵深（按需）**：多内核版本（含旧系统指纹）、内核自动更新与签名、macOS/Linux 支持、TLS/JA3 层增强评估。

## 14. 风险与限制（如实说明）

1. **不存在绝对不可检测**：内核路线显著降低 JS/渲染面风险，但 IP 质量（是否机房/黑名单）、账号行为、访问节奏仍是主要封禁因素。
2. **TLS/JA3、HTTP2 帧指纹**：取决于所选内核是否含网络层补丁；普通指纹内核默认不覆盖，需评估专用内核。
3. **内核供应链**：开源内核的维护频率、漏洞修复、版本更新与许可合规必须纳入长期维护；二进制需哈希校验与来源锁定。
4. **体积与更新**：单内核包 200–300MB，安装包显著变大；多内核与自动更新需要独立分发通道与签名。
5. **资源**：100 并发约需 15–30GB+ 内存；默认并发 20 的软上限必须保留。
6. **扩展**：完整支持依赖内核版本；部分企业策略扩展在未签名场景可能受限。
7. **平台差异**：v1 仅 Windows x64；macOS/Linux 的内核构建与签名另立计划。

## 15. 已确认决策（速览）

1. **100 口径**：100 = 存储档案上限；同时打开默认 20、可配至 100，超出排队并提示内存。
2. **代理类型**：HTTP / HTTPS / SOCKS5；认证支持账号密码与 IP 白名单；vmess/trojan 由用户本地客户端转 127.0.0.1 端口后绑定。
3. **指纹默认**：Canvas/Audio 轻噪开 + 稳定种子；WebGL 模板配对；提供关闭与自检页。
4. **Agent 目标**：显式绑定「Agent 默认窗口」，不跟随焦点；工具返回 profileId/窗口 id。
5. **IP 检测**：默认 `https://api.ipify.org?format=json`，可配置；国内可用 `https://myip.ipip.net`；地理查询可选、默认关。
6. **其他**：扩展按窗口启用（能力以内核为准）；本地 API 默认关闭、token 鉴权；P3 做批量/代理池/分组/Cookie；团队与云手机不纳入 v1。

## 16. 比特浏览器对照（结论）

- 比特浏览器公开形态：Chrome/Firefox 内核深度改造、多内核版本、一窗口一环境一 IP、HTTP/SOCKS5、按窗口数售卖、本地 API + RPA + 团队协作。
- 本方案采用同型路线：**改造内核 + 独立进程/目录 + 独立指纹与代理 + 管理器 UI + CDP/本地 API**；差异在于起步使用开源指纹内核，先做管理与自动化闭环，再视风控强度升级内核（自维护或商业授权）。
- 与之前应用层方案的对比：应用层能覆盖常见 JS 面，但无法覆盖 TLS/JA3、深层字体/协议与完整扩展；内核路线才能把风险压到与比特浏览器同级。

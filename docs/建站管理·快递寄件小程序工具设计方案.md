# 建站管理 · 快递寄件小程序工具 设计方案

> 落点：工作台「建站管理 → 快递寄件小程序」，一个账号一部自己的微信小程序；
> 账号下的寄件点只是 C 端可选的取件位置。
> 代码：`packages/contracts/src/kuaidi.ts`、`backend/src/kuaidi/`、`frontend/src/app/kuaidi/`、
> `frontend/src/app/admin/_components/kuaidi-tab.tsx`、`kuaidi-miniprogram/`。

## 一、产品口径

1. **一个账号一部小程序，站点只是寄件点**：AppID/密钥、出包台账与收款账户都挂在账号级；
   账号下可建任意多个寄件点（位置/营业时间/电话），数量不设配额，平台不审核、不暂停。
   C 端进小程序后按 AppID 拉营业中的寄件点让顾客选，或扫码/分享链接带 `?site=寄件点码` 直达；
   跨账号数据不互通。
2. **平台不经手资金**：在线支付时款项直进店主的微信商户号；平台只做通道下发与状态推进，
   不记账、不代扣、不代退。商户号放在账号级「收款账户」里，可被名下多个寄件点共用；
   平台级「允许在线收款」关闭后，即使账户配齐也按线下登记。
3. **运价只由店主配置**：首重/续重/偏远省份/偏远附加/保价费在站点内按快递公司分别配，
   端上只提交重量、尺寸、收件省份等输入，任何金额字段都不采信。
4. **交易与客服解耦**：绑定 AI 客服（service-desk）只影响客服入口，关掉或没绑好不影响下单支付；
   联系方式与在线客服二选一兜底。
5. **双支付模式**：`ONLINE` 微信在线支付（商户号可用时）、`OFFLINE` 线下收款登记（默认兜底），
   订单上的 `payMode` 在创建时定格，之后不随配置变化。

## 三、数据模型（7 张表）

### 3.1 `kuaidi_sites`（寄件点）

- 身份：`ownerUserId`、可选的 `enterpriseId/enterpriseUserId`、`siteCode`（全局唯一，扫码/分享定位用）；
- 位置：`province / city / district / addressLine / lng / lat / businessHours / phone / pickupNote`，
  顾客在小程序里按这里的地址选点；
- 门面：`name/logo/slogan/themeColor/notice`，`serviceContact`（电话/微信/邮箱 JSON）、
  `deskSiteKey`（绑定 AI 客服服务站）；
- 模块开关 `toggles`（9 个键）：`indexNotice / deskChat / contact / insurance / addressBook /
  myOrders / protocol / pickupTime / tracking`，端上关掉的模块整块不渲染；
- 计费与规则：`insuranceEnabled / insuranceRate / insuranceMax / maxWeightKg /
  payMinutes / pickupSlots / protocolText`；
- 收款：`payAccountId` 指向账号级收款账户，`0` = 用账号下第一个启用账户；
- 状态：`DRAFT / ONLINE / CLOSED`。寄件点数量不设配额，平台不参与审核与停服。

### 3.2 `kuaidi_companies`（报价规则）

站点内可多条（同一快递公司的不同产品线也允许）。核心字段：
`code/name/logo/deliveryDays/firstWeightKg/firstPrice/extraWeightKg/extraPrice/
remoteProvinces(JSON)/remoteExtra/remark/status/sort`。

### 3.3 `kuaidi_orders`（订单）

- 单号：`KD + yyyyMMddHHmmss + 6 位随机`，全表唯一——账号级小程序要按回调单号全局定位订单；
- 收寄双方为**下单时刻快照** JSON，之后地址簿改动不影响历史单；
- 金额逐项落库：`baseFee / extraFee / remoteFee / insuranceFee / totalAmount`，
  另有 `volumeWeightKg / chargeWeightKg / insuredValue` 留痕；
- 支付：`payMode / payAccountId / payState / transactionId / prepayId / paidAt / closedAt / refundedAt / expireAt`，
  `payAccountId` 记录创建时实际下发的收款账户；`0` 表示当时未配置在线收款，补支付时按默认账户处理；
- 履约：`status`（8 态）、`pickupSlot / remark / trackingNo / cancelReason`；
- 顾客归属：`customerId / openid / createIp`，公开通道按 `siteId + openid` 双条件过滤。

### 3.4 `kuaidi_order_events`（履约轨迹）

只追加：每次状态推进写 `status/note/operator`，买家端订单详情按时间正序展示，不覆盖历史。

### 3.5 `kuaidi_addresses`（地址簿）

`type(SENDER/RECEIVER) + 收寄信息 + isDefault`；同一 `(siteId, openid, type)` 下默认地址唯一
（设默认时同类型其余地址自动取消默认）。

### 3.6 `kuaidi_customers`（寄件点顾客）

`(siteId, openid)` 唯一，累计 `orderCount / paidOrderCount / totalAmount / lastOrderAt`。
店主可停用某位顾客：其令牌之后的顾客态读写（我的订单、地址簿）一律 403，匿名查单不受影响。
登录下单或补建档案时才会落顾客表，纯匿名单（无 openid）不建档。

### 3.7 `kuaidi_pay_accounts`（账号级收款账户）

`ownerUserId + mchId` 唯一；字段 `name / enterpriseId / mchId / certSerial / enabled` 与两段密文
`apiV3KeyCipher / privateKeyCipher`（按账号 + 商户号 + 字段派生密钥加密，改 AppID 不会作废）。
「可用」= 四项凭据齐全且启用；多个寄件点可指向同一账户，站点侧 `payAccountId = 0` 时取第一个可用账户。
平台不落账，也不保存任何可回退的资金动作。

## 四、计价与支付

### 4.1 唯一计价入口 `quoteFees`

`backend/src/kuaidi/kuaidi.shared.ts`：

1. 体积重 = 长×宽×高 ÷ 6000；计费重量 = max(实重, 体积重)，向上取整到 0.1kg；
2. 首重内收首重价，超出部分按续重单位向上取整累加；
3. 收件省份命中 `remoteProvinces` 时加偏远附加费；
4. 保价费 = min(声明价值, insuranceMax) × insuranceRate（`insuranceMax = 0` 表示不限）；
5. 全部金额在「分」上整数运算后回元，避免浮点误差。

前端报价接口与下单接口共用该函数；下单时服务端按提交的重量/尺寸/省份重新算一遍，
与报价不一致时以服务端为准，端上金额不参与计算。

### 4.2 支付

- 创建订单时若寄件点的收款账户可用且平台允许在线收款，`payMode = ONLINE` 并返回小程序支付参数，
  同时把实际下发的 `payAccountId` 落在订单上；否则 `OFFLINE`，页面提示线下付款，
  订单进入待取件前由店主「登记已收款」。
- 微信支付回调 `/api/public/kuaidi/pay/notify/:accountId`：URL 带收款账户 id，按该账户的 APIv3 密钥解密；
  解密后先核对 `mchid` 与账户一致，再按全局唯一的 `orderNo` 找订单。只认「账户一致 + 待支付 + SUCCESS + 金额一致」；
  账户与订单的 `payAccountId` 不符、金额不符、单已关闭都属于确定性结果，不要求重投；
  仅「单号暂时查不到」返回失败让微信继续重试。
- 未支付订单超过 `payMinutes` 由调度器（默认每 60s）关闭；`KUAIDI_SCHEDULER_DISABLED=1`
  可停用，`KUAIDI_SCHEDULER_TICK_MS` 可调间隔。

### 4.3 履约状态机

`PENDING_PICKUP → ACCEPTED → PICKED_UP → IN_TRANSIT → DELIVERED → COMPLETED`，
另有 `EXCEPTION / CANCELLED`。每个动作有前置状态白名单（`ACTION_FROM`），
非法跃迁直接拒绝；退款只登记线下处置（`REFUND` → 已取消 + payState=REFUNDED），平台不代退。

## 七、小程序端（`kuaidi-miniprogram/`，8 页）

| 页面 | 职责 |
| --- | --- |
| `pages/index` | 选寄件点（未选或换点时）、门面、入口宫格（寄件/查单/我的订单/地址簿）、客服与联系方式 |
| `pages/create` | 收寄双方、包裹、报价比价、取件时段、协议勾选、提交与支付 |

| `pages/order-detail` | 状态、轨迹、收寄信息、费用明细、继续支付/取消 |

出包由 `injectConfig` 实际写入 `apiBase / appName`；`siteCode / themeColor / deskSiteKey` 保留空串占位
（`siteCode` 仅作单点部署时可手填的默认寄件点码），`appId` 由 `injectAppId` 写入 `project.config.json`。
端上启动时：链接/扫码带 `?site=寄件点码` 则直接落点；否则按小程序 AppID 拉营业中的寄件点，
只有一个直接进、多个交给首页选，选中后写本地并重新登录（令牌按寄件点签发）。
所有公开接口都带 `?site=寄件点码`，**不使用端上传的 siteId 做权限依据**；
门面以 `bootstrap` 实时值为准，改店名/主题色不需要重出包。
`backend/src/kuaidi/kuaidi.template.spec.ts` 守住模板完整性：页面三件套、配置占位可注入、版本号可读。

## 九、安全与边界

1. **站点寻址**：公开接口一律用小程序 AppID（选点列表）或寄件点码反查寄件点，端上传的 `siteId` 不参与鉴权；
   顾客令牌按「场景(EXPRESS) + 寄件点 id + customerId」签发，进不了 `/enterprise/**`。
2. **匿名最小面**：bootstrap/quote 只回展示字段与启用报价，不携带任何凭据；按 IP 限流。
3. **查单防枚举**：单号 + 手机号双因子，独立限流窗口，响应禁止缓存（含收寄地址与手机号）。
4. **金额不可信**：端上只提交输入项，金额由服务端 `quoteFees` 重算；回调金额与订单不符直接判定失败。
5. **越权隔离**：顾客态读写按 `siteId + openid`（或 `customerId`）双条件过滤；
   地址、订单、顾客列表都带寄件点条件，店主接口再按 `ownerUserId` 收口。
6. **资金边界**：平台不代扣、不代退；退款只做状态登记，线下处置由店主完成；
   平台级支付闸门关闭时不下发任何支付参数。
7. **出包安全**：模板只改内存副本；占位被填过、缺 `app.json/config.js/project.config.json`、
   超过微信主包上限时都在出包前拒绝并给出可执行提示。

## 十、验证与已知边界

- 单元验证：`cd backend && pnpm test kuaidi` 覆盖模板完整性与出包注入；
  计费引擎为纯函数，回归时优先补 `quoteFees` 的边界用例（体积重、取整、保价上限、偏远命中）。
- 端到端验证：以「建站 → 配快递公司 → 出包 → 微信开发者工具导入 → 下单/支付/查单」为主路径，
  离线收款与在线收款各走一遍；回调重投用金额不符与单号不存在两种报文验证。
- 已知边界：小程序域名需店主在微信后台自行登记 `request` 合法域名与 `web-view` 业务域名；
  取件时段为自由文本清单，不校验运力；轨迹由店主手动推进，未接快递公司物流接口。

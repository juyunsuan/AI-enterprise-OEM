# 建站管理 · 圈子社区小程序工具 设计方案

> 落点：工作台「建站管理 → 圈子社区小程序」（`/circle`）。
> 参考源码：`duokegroup-master`（多客圈子社区系统，UniApp + ThinkPHP6，Apache-2.0）。
> **只借鉴产品形态与业务口径，不复制其源码、文案与图片**；实现全部按本项目技术栈重写。
> 代码：`packages/contracts/src/circle.ts`、`backend/src/circle/`、`frontend/src/app/circle/`、
> `frontend/src/app/admin/_components/circle-admin-tab.tsx`、`circle-miniprogram/`。

## 一、产品口径

1. **一个账号一个社区，账号负责人就是小程序管理员**：社区实例按 `ownerUserId` 唯一；
   AppID/密钥、出包台账都挂在账号级（`miniprogram_apps` / `miniprogram_tenant_releases`，`scene=CIRCLE`、`shopId=0`）。
   不做「平台方 → 入驻商 → 消费者」三层，也不做商户入驻审核。
2. **C 端成员独立于站内账号**：`circle_users` 按 `communityId + openid` 唯一，
   令牌沿用 private-mini 顾客 issuer（`scene=CIRCLE + shopId=communityId + customerId`），
   进不了 `/enterprise/**`；站内账号也不会被当成社区成员。
3. **圈子是社区内部单元**：管理员建分类与话题；成员可申请建圈（受平台「每人建圈上限」约束），
   管理员审核；圈主/圈管只能管理自己的圈子与成员。
4. **内容首期范围**：图文帖（最多 9 图）、话题、一级评论与楼中楼回复、点赞、收藏、关注圈子/用户、
   站内消息、举报与管理员处置。活动与勋章按参考包属后续项，首期不做。
5. **平台不代传微信**：与快递/卡密/品牌商城一致，输出统一源码分发包，用户在微信开发者工具里自填参数并上传。

## 二、与参考包的关系

参考包的核心模型是：`category`＝圈子/博主、`goods`＝帖子、`goods_comment`＝评论、
`category_follow` / `user_fans`＝关注与粉丝、`goods_like`＝点赞、`message`＝消息、`report`＝举报。
本实现保留这套**业务语义**，但做了三处按本项目口径的收敛：

| 参考包 | 本项目 |
| --- | --- |
| 单站点 + `admin_id` 管理 | 一个账号一个社区；账号负责人即管理员；平台侧只做板块与停服 |
| 圈子与分类混在 `category`（`fid` 自关联） | 拆成 `circle_categories`（管理员维护）+ `circle_groups`（圈主运营） |
| `is_sh` / `is_ding` 等状态位散落 | 统一状态机：圈子 `PENDING/ACTIVE/REJECTED/DISABLED`、帖子 `PENDING/PUBLISHED/REJECTED/HIDDEN/DELETED` |
| 无计费、无 AI、无数字资产 | 复用平台底座补齐（见第三节） |

## 三、复用底座映射

| 平台底座 | 圈子社区怎么用 |
| --- | --- |
| `private-mini`（小程序主体/出包台账） | `scene=CIRCLE`、`shopId=0`；出包器 `collectTemplate + buildStoreZip`；台账 `miniprogram_tenant_releases` |
| `tool-launch`（启动设置/计费） | 新增 `toolCode=circle`、价目行 `circle`；管理端写操作与 C 端公开通道都走同一闸门；出包前 `requireStarted` |
| `points`（积分总账） | 周期/按量账单统一经 `settlePeriod` 写 `point_transactions` + `tool_subscription_bills`，幂等键 `tool_launch:circle:{subId}:{periodKey}` |
| `service-desk`（AI 客服） | 社区只存 `deskSiteKey` 绑定引用；小程序「客服」页用 `web-view` 打开 `/embed/service-desk?key=`；不新建会话表、不新增客服类型 |
| `ai-gateway`（模型网关） | AI 运营助手（公告/圈子简介/帖子摘要/周报）统一走 `aiChat`，`module=circle`、`charge.code=ai_service`，自动记用量与积分 |
| 数字资产管理 | 管理员 Logo/封面/分享图用 `AssetReferencePicker` 从 `/assets` 选择；用户 UGC 图片只落 OSS，不污染账号素材台账 |
| 内容审核 | 复用 `PublishReviewService.guard`（`community_post` 场景）审文本；图片上传后 `guardImage`，命中拦截即删对象 |
| OSS/StorageService | UGC 图片经 `StorageService.put` 落桶；出包 zip 经 `SystemAssetService.put` 入台账 |

## 五、数据模型（迁移 `0146_circle_community`）

1. `circle_communities`：一个账号一行。门面（名称/Logo/封面/标语/简介/主题色/公告）、
   审核开关（`join_approval` / `allow_user_create_circle` / `post_review` / `comment_review`）、
   `ai_assistant_enabled`、`desk_site_key`、客服联系方式、协议/隐私/关于、平台停用留痕。
2. `circle_categories`：管理员维护的分类，`(communityId, name)` 唯一。
3. `circle_users`：C 端成员，`(communityId, openid)` 唯一；`ACTIVE/MUTED/BANNED` + 计数。
4. `circle_groups`：圈子；`creatorUserId`（0＝管理员创建）、分类、加入方式、状态机、计数、推荐位。
5. `circle_group_members`：角色 `OWNER/ADMIN/MEMBER`，状态 `PENDING/ACTIVE/MUTED/BANNED`，`(groupId,userId)` 唯一。
6. `circle_group_follows` / `circle_user_follows`：关注圈子、关注用户。
7. `circle_posts`：图文帖；`images` JSON；状态机；置顶/精选；赞/评/看/收藏计数与热度分。
8. `circle_topics` / `circle_post_topics`：话题与帖子关联。
9. `circle_comments`：`parentId=0` 为一级评论，非 0 为楼中楼；`replyToName` 快照。
10. `circle_post_likes` / `circle_comment_likes` / `circle_post_favorites`：唯一索引兜住并发双击。
11. `circle_post_views`：`(postId, visitorKey, day)` 唯一——按浏览量计费的去重事实；
    登录用户键为 `u:<openid>`，匿名为 `ip:<IP>`。
12. `circle_reports`：举报对象/原因/状态/处置动作与处置人。
13. `circle_notifications`：站内消息（赞/评论/回复/关注/加入/审核/系统）。

同时给既有底座加两列：
- `module_pricing.usage_billed`：按量口径是否真正期末出账（默认 0，只计量）。
- `tool_usage_daily.views`：内容浏览量（帖子详情去重打开）。

## 七、C 端公开通道（`/api/public/circle/**`）

- 寻址：`appId`（正式）或 `code`（本地调试/分享）；**端上传的 communityId 从不作为权限依据**。
- 匿名可读：`bootstrap`、分类、圈子列表/详情、帖子列表/详情、评论、话题、搜索、用户主页。
- 需成员令牌：登录后的资料、发帖、评论、点赞/收藏、关注、加入/退出、举报、消息、收藏列表。
- 浏览计量：`post/detail` 按 `(postId, visitorKey, day)` 去重，首次打开才累加帖子 `viewCount`
  并调用 `ToolLaunchMeterService.view('circle', ownerUserId)` 写 `tool_usage_daily.views`。
- 未启动/欠费停服/平台停用：`toolOpen('circle', ownerUserId)` 为假时整条公开通道 503，
  文案直接指向「建站管理 → 启动设置」。
- 限流：匿名读 240 次/分/IP，写 60 次/分/IP，登录 20 次/分/IP，上传 20 次/分/IP。

## 八、启动与计费

新增 `toolCode=circle`，价目行 `circle` 由迁移种子写入（默认 `FREE`，平台管理员可改）。
支持口径：`FREE` / `DAY` / `DAY30` / `YEAR` / `USAGE_PV`（访问量）/ `USAGE_BYTES`（流量）/
**`USAGE_VIEW`（浏览量，新增）**。

- **周期口径**：启动预付首期，到期日批续扣；欠费进宽限、超宽限停服、充值自动补扣复活；数据不删。
- **按量口径**：本轮补齐了「真正出账」能力：
  - `module_pricing.usage_billed=1` 时，账期结束按 `tool_usage_daily` 聚合；
  - 先扣每期免费量，再按 `usage_unit_size` 向上取整乘单价，低于起扣额按起扣额；
  - 账单走同一 `settlePeriod`，幂等键仍由持久期次推导；
  - `usage_billed=0`（既有工具默认）时保持「只计量、不出账」，不改变存量行为。
- **浏览量**：只认 `circle_post_views` 去重后的打开，同一访客同一天刷新不重复计费。
- **流量**：沿用公开通道响应字节计量；图片直链由 OSS/CDN 承载，CDN 层流量日志接入前列为后续项。

## 九、AI、数字资产与客服

1. **AI 客服**：社区只存 `desk_site_key`，保存时校验该站点属于当前账号；
   小程序「客服」页 `web-view` 打开 `/embed/service-desk?key=`，未绑定则展示电话/微信。
2. **AI 运营助手**：管理员侧生成公告、圈子简介、帖子摘要、社区周报；
   统一走 `aiChat`，`module=circle`、`operation=circle_*`、`charge.code=ai_service`，
   缺模型时给出「模型服务 → 模型设置」的可执行引导。
3. **数字资产**：管理员 Logo/封面/分享图通过 `AssetReferencePicker` 从 `/assets` 选择；
   用户 UGC 图片只落 OSS（`circle/{communityId}/{yyyyMM}/...`），不登记进账号素材台账；
   上传后立即图片安全检测，命中拦截删除对象。

## 十二、安全与边界

1. **租户隔离**：所有业务查询带 `communityId`；C 端社区由 AppID/社区码解析，请求体 id 不作为权限依据。
2. **身份隔离**：成员令牌 `scene=CIRCLE + shopId=communityId + customerId`，与站内会话物理隔离；
   公开主页按 `(communityId, id)` 双条件读取，防跨社区枚举。
3. **内容安全**：发帖/评论/建圈文本送 `PublishReviewService`；图片上传后送 `guardImage`；
   举报可隐藏/删除/封禁，处置同步通知作者。
4. **越权**：圈主/圈管只能管理自己的圈子；不能操作圈主；成员只能删除自己的帖子/评论。
5. **计费不可刷**：浏览量按访客日去重；按量账单幂等键由持久期次推导；关闭 `usage_billed` 时只计量。
6. **发布安全**：平台不代传微信；出包前校验模板完整性与主包体积；凭据只回掩码。
